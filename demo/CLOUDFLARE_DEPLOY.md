# Owner-operated Cloudflare deployment — no MCP required

This publishes only the existing competition Worker `hackbr-2026-warden-p0`. No new Worker, billing change, domain change, secret, binding, production service, or public preview is intended. The 25 Nov PQC release version `382db3b9-9160-4648-97cb-2f49c8747e96` was confirmed at 100% traffic, with preview URLs disabled, no bindings and working public PQC and tamper verification. See [recorded proof](judge/recorded-pqc-release.json). Verify that it is still the current version before proceeding; if not, stop and review the change before uploading anything. The earlier `84a14798-da98-4e7b-a493-ef1b6c288aab` remains available for rollback.

1. Check out the clean, CI-passing release commit in the owner's existing environment. Use Node 24.7+ for the tests (the static builder does not require the post-quantum primitives). Build with `node judge/build.mjs` and run the published CI tests.
2. Use the official [Wrangler CLI](https://developers.cloudflare.com/workers/wrangler/) and owner-controlled credentials through its normal login flow. Do not paste tokens into ChatGPT. If no eligible authenticated account exists, stop for owner authorization; never fall back to a different account. `npx wrangler@4 whoami` should display the existing Royalcrafter account. `npx wrangler@4 deployments list --config judge/wrangler.toml` must show the exact current target and version. No other Worker is in scope.
3. Run `npx wrangler@4 deploy --dry-run --config judge/wrangler.toml` and review the name, module, no bindings and no paid changes. Record the Wrangler version used. If the dry run or current deployment does not match the expected isolation scope, stop.
4. The owner may deploy the reviewed build with `npx wrangler@4 deploy --config judge/wrangler.toml`. This creates a version and sends it 100% of traffic to the existing Worker. Verify the new version and deployment ID, public root and `/console`, `/quantum`, `/lifecycle-report.json`, `/quantum-hardware-smoke.json`, and exercise the genuine/missing evidence checks. Preserve the previous deployment for rollback; do not delete old versions or unrelated resources.

Do not treat a successful build or an uploaded version as proof of a public release. The [Cloudflare deployment docs](https://developers.cloudflare.com/workers/configuration/versions-and-deployments/) describe version/deployment separation and rollback. The [version URLs docs](https://developers.cloudflare.com/workers/versions-and-deployments/version-urls/) explain the existing `preview_urls = false` setting.
